# AI-помощник по погоде (Lite, этап 1)

Локальное веб-приложение на FastAPI. OpenAI-модель выбирает MCP-инструменты, а погода получается только через заданный удалённый сервер `https://weather.chukai.io/mcp`. Приложение не создаёт собственный MCP-сервер и не вызывает погодные API напрямую. Интерфейс и ответы рассчитаны на русский язык.

Код разделён на веб-приложение, агента и MCP-клиент. Сейчас реализован Streamable HTTP; модуль можно расширить транспортом stdio для отдельного этапа. Excel и этап 2 не реализованы.

## Требования

- Windows 10/11 и Python 3.11 или новее (64-bit).
- Доступ в интернет к OpenAI API (или совместимому API) и `weather.chukai.io`.
- Ключ OpenAI API. Не присылайте его в чат и не добавляйте в репозиторий.

## Запуск в Windows PowerShell

Откройте PowerShell в папке `mcp-weather-assistant` и выполните команды по очереди:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

В `.env` вставьте ключ только после `OPENAI_API_KEY=` и сохраните файл. Ключ хранится локально в `.env`, исключённом из Git. При необходимости настройте `OPENAI_MODEL`. Для совместимого API задайте `OPENAI_BASE_URL` и модель; обычно `OPENAI_BASE_URL` оставляют пустым.

Запустите приложение:

```powershell
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Остановка: `Ctrl+C` в окне PowerShell. Выход из окружения: `deactivate`.

## Настройки

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `OPENAI_API_KEY` | Ключ модели, нужен для диалога | пусто |
| `OPENAI_BASE_URL` | Адрес OpenAI-совместимого API | SDK default |
| `OPENAI_MODEL` | Модель | `gpt-4.1-mini` |
| `WEATHER_MCP_URL` | Адрес MCP-сервера | `https://weather.chukai.io/mcp` |
| `MCP_TIMEOUT_SECONDS` | Таймаут MCP | `20` |
| `OPENAI_TIMEOUT_SECONDS` | Таймаут запроса к модели | `45` |
| `MAX_TOOL_CALLS` | Лимит вызовов инструментов за ответ | `5` |

История хранится в памяти, отдельно для каждого UUID сессии. Кнопка «Новый диалог» очищает историю текущей сессии; перезапуск сервера также очищает историю. `/api/health` проверяет MCP `initialize` и `tools/list`, но не OpenAI API. Интерфейс открывается без ключа и при недоступности MCP; для реального ответа модели ключ необходим.

## Проверка MCP

При открытии страницы `/api/health` вызывает официальный Python MCP SDK: `initialize`, затем `tools/list`. Это не обычный GET. Для вывода описаний и схем инструментов в консоль используйте:

```powershell
python .\scripts\inspect_mcp.py
```

Скрипт не придумывает названия и не вызывает инструментов автоматически.

### Фактически полученные данные

- **Официальный MCP SDK:** установлен `mcp 1.30.0`; скрипт `inspect_mcp.py` успешно выполнил `initialize` и `tools/list`. Сервер сообщил `Smart MCP Server 1.0.0`, SDK согласовал протокол `2025-11-25`, получил идентификатор сессии и 12 инструментов.
- **Транспорт:** сервер ответил на Streamable HTTP запросы с `Content-Type: text/event-stream` и HTTP 200; Streamable HTTP подтверждён реальным обменом. Дополнительно ручной JSON-RPC handshake согласовал версию `2025-03-26`.
- **Имена из `tools/list`:** `get_air_quality`, `batch_get_air_quality`, `get_weather_forecast`, `batch_get_weather_forecasts`, `geocode_location`, `batch_geocode_locations`, `get_historical_weather`, `batch_get_historical_weather`, `get_marine_forecast`, `batch_get_marine_forecasts`, `interpret_weather_code`, `batch_interpret_weather_codes`.
- **Основные схемы:** `geocode_location` требует `name`, дополнительно принимает `count`, `language`, `format`. `get_weather_forecast` требует `latitude`, `longitude`; дополнительно принимает `temperature_unit`, `wind_speed_unit`, `precipitation_unit`, `timezone`, `forecast_days`, `current_weather`, `hourly`, `daily`.
- **Реальные безопасные вызовы:** `geocode_location` и `get_weather_forecast` выполнены для Екатеринбурга и Казани. Затем через `WeatherMCPClient` проекта повторены `tools/list`, геопоиск и прогноз для Екатеринбурга официальным SDK; схемы сохранились как JSON-объекты, ответы обоих MCP-инструментов имели `isError=false`. В замере 21.11.2026 сервер вернул для Екатеринбурга `-2.4` и ветер `7.6 km/h` на `2026-11-21T05:00`; предыдущий замер вернул для Казани `3.7` и `7.7 km/h` на `2026-11-21T02:45`. Значения относятся к указанным временам, это не обещание актуальности позднее.

Имена, схемы и ответы в этом разделе получены от сервера. Трассировка в приложении показывает настоящее имя вызванного инструмента, аргументы и фактический результат/ошибку.

## Что проверено и что осталось

**Реальные проверки:**

- Python `compileall` завершился без ошибок; `pip check` сообщил `No broken requirements found`; импорт приложения и SDK прошёл.
- Официальный OpenAI API ответил на минимальный запрос `OK` с моделью `gpt-4.1-mini`. Ключ не выводился.
- Через FastAPI `TestClient` пройден полный сценарий в одной сессии: «Какая сейчас погода в Екатеринбурге?» → «А в Казани?». Оба ответа HTTP 200; OpenAI сам выбрал `geocode_location`, `get_weather_forecast`, `interpret_weather_code`; все MCP-вызовы успешны, для второго города выполнен новый геопоиск и прогноз.
- В этом тестовом ответе для Екатеринбурга были `−1.6 °C`, ветер `12.5 km/h`, время `2026-11-21T22:00`; для Казани — `4.0 °C`, ветер `4.4 km/h`, время `2026-11-21T20:00`. Это результаты замера на указанное время.
- `/api/health` через официальный SDK возвращает HTTP 200, `mcp=available` и 12 имён инструментов. Сценарий недоступного MCP проверен через TestClient: health остаётся HTTP 200 с `mcp=unavailable`, главная страница открывается.
- `/api/chat` без ключа возвращает инструкцию настройки, не придумывая погоду. `/api/new-chat` и `node --check .\static\app.js` проверены.

**Найденная и исправленная причина ошибки подключения OpenAI:** пустая запись `OPENAI_BASE_URL=` в `.env` оставляла SDK с пустым URL (`UnsupportedProtocol`). Приложение теперь явно использует `https://api.openai.com/v1`, когда поле пустое. После правки минимальный запрос и полный сценарий с реальной моделью прошли. При изменении настроек перезапустите uvicorn.

**Имитационные проверки:** изоляция историй разных UUID-сессий и очистка истории нового диалога; лимит вызовов; обработка MCP/LLM ошибок и отсутствия инструментов. Эти проверки использовали имитацию модели.

**Осталось проверить вручную:** визуально осмотреть отображение страницы в браузере. Автоматизация Windows остановилась, так как не смогла надёжно определить URL текущей вкладки. HTTP и FastAPI проверки прошли, но скриншот браузера не получен. Для сдачи сделайте скриншоты успешных ответов и отдельного недоступного MCP-сервера; не показывайте `.env` или ключ.

Для повторной проверки отказа временно задайте `WEATHER_MCP_URL=http://127.0.0.1:1/mcp`, перезапустите приложение и проверьте `/api/health` и чат, затем верните штатный URL.
## Материалы для сдачи Lite

Сделайте скриншоты браузера с ответами по Екатеринбургу и Казани, раскрытой панелью «Вызовы MCP» (реальные имена, параметры, статусы и результат), индикатором MCP и отдельным сценарием недоступности. Не показывайте `.env` или ключ. В кратком описании укажите стек, подтверждённый транспорт, имена инструментов из `tools/list` и разделите пройденные и непроверенные проверки. Не включайте ключи и вымышленные результаты.
